- 8214 当前使用无通信能力的 PDP 2.0，生产日志不会提供可用的 PDP/PDP 总电流或总功率；Cyber Power 的电池分析只能使用 Battery Voltage 与已注册电机 Supply Current 总和。用户界面统一称为“整机”，但方法与限制必须明确该口径不是 PDP/PDH 总电流，不得表述成真实电池总电流、纯电池内阻、SOC、容量或整机总 Wh。
- Cyber Power vendordep 只允许写入 EnergyLogger V2，彻底舍弃 V1 写入 API 与双写路径；网页端必须继续兼容读取既有 V1 日志，并同时支持 V2。
- 限流模拟只能以 V2 Manifest 的 Leader 电机组为目标：一台 Leader 与其全部直接 Followers 使用合计 Supply Current 上限；不得把 canonical 子系统节点、Follower 单机或用户确认的聚合路径伪装成电机组。V1 继续用于历史分析，但因没有 Manifest 不提供限流模拟。
- EnergyLogger V2 的高级分析范围只保留估算驱动效率、减速比推荐和分状态功耗；机器人端复用既有 Supply Current、Stator Current 与全局电池电压，唯一允许新增的 CAN 状态信号是每个独立电机或同构组 Leader 的原生 Rotor Velocity，禁止为 Follower 或其他诊断字段新增信号；原生转速、TalonFX 反馈单位换算比例和被推荐的有效减速比必须保持独立。
- Cyber Power vendordep 的 Java 根包路径固定为 `com.nextinnovation.cyberpower`；源码、测试、Javadoc、发布坐标说明和机器人 import 全部使用该路径，不得改用 `com.nirobotics.cyberpower`。
- EnergyLogger v2 的执行顺序固定为：先让 Cyber Power 网页冻结并支持 v1/v2 增量日志契约及新分析功能，再构建、测试并发布可匿名安装的 vendordep，最后才迁移 `NI-8214-2026`；网页兼容和 vendordep 发布门禁未通过前，不修改生产机器人能量记录路径。
- `EnergyLogger` 采用全局单例，并通过 `createSubsystem(subsystemName)` 创建和持有轻量 `EnergySubsystem` 对象；机器人子系统在构造时保存该对象并通过它注册本子系统电机，在完成输入刷新后调用该对象的 `periodic()`，使用本子系统统一且独立的时间戳采样和积分。Robot 每周期末仍调用 `EnergyLogger.getInstance().periodicRobot()` 完成整机采样、跨子系统汇总、数据对账和日志收尾；`EnergySubsystem` 不是独立 logger，不能取代整机统一汇总。
- `EnergyLogger` 提供一次性的全局 `registerTimeSource(TimeSource)`，其中 `TimeSource.nowMicros()` 返回微秒；所有 `EnergySubsystem` 必须共用同一时钟域，但各自保存采样时间和 `dt`。默认时间源使用可被日志框架接管的 `RobotController.getTime()`；AdvantageKit 使用者可显式注册 `Logger::getTimestamp`。时间源必须在首次采样前注册并随后锁定；允许相同时间戳，拒绝时间回退。
- `EnergySubsystem.periodic(currentState)` 在采样本子系统全部电机时同时记录当前执行状态；优先直接接受使用方自己的枚举并以 `name()` 形成稳定值，同时允许稳定字符串作为兼容入口。状态按 Sample-and-Hold 语义生效：先把上一功率和上一状态积分到本次时间戳，再更新状态和电机样本。日志只在子系统层记录状态及变化，网页自动将其继承到该子系统的聚合节点和全部电机；Robot Mode 与子系统状态保持为两个独立分析维度。
- EnergyLogger v2 作为 `cyber-power` 同仓库内独立构建和发布的极简 Java vendordep；核心只依赖 Java 17 与官方 WPILib，不依赖 CTRE、REV、AdvantageKit 等第三方库。公开 API 只把封闭的已知电机型号做成 `MotorType` 枚举且禁止 `UNKNOWN/CUSTOM`；字段和 Leader/Follower 等能由方法名表达的概念不用枚举。子系统名只在创建 `EnergySubsystem` 时传入；该对象注册电机时直接传电机名、型号和正减速比（`>1` 表示减速），Follower 额外直接传本子系统内的 Leader 电机名；设备与日志框架由使用者通过通用 source/sink 适配。
- 当前公开 descriptor 指向不可变 V2-only vendordep `2026.2.2`，Maven 坐标为 `com.nextinnovation.cyberpower:cyberpower-java:2026.2.2`，永久 UUID 为 `82ed958d-ee21-437a-90e5-dfa702a2de63`；该版本只写 V2.3，原生 Rotor Velocity 单位固定为 `rad/s`。V2.3 适配器必须把 Supply Current 规范为从直流母线取电为正、向母线返回为负，把 Stator Current 规范为 motoring 为正、regenerative braking 为负；两者都不得随转子方向翻转。历史不可变 `2026.2.0` 继续只写 V2.1，`2026.2.1` 只写 V2.2；网页必须读取 V2.1/V2.2/V2.3 并在解析边界统一单位和符号语义。已知包含 V1 writer 的 `2026.1.0/2026.1.1` 不得出现在公开 descriptor、Maven metadata 或版本目录中；匿名安装 JSON 与 Maven 根分别发布到 `https://power.team8214.com/vendordep/CyberPower.json` 和 `https://power.team8214.com/vendordep/maven`。
